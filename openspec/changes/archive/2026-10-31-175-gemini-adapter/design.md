## Context

The daemon is driven by hooks (`HookReceiver` → bus `hook` → sessions, push, live status), by transcripts (`TranscriptService` with one `TranscriptFormat` per agent) and by the tmux pane (input, keys). `AgentAdapter` (changes 66, 80, 163) holds what differs between agents. Codex hooks resemble Claude Code's; Gemini's do not.

Facts about Gemini CLI 0.66.0 used here (read from the npm bundle, not run):
- Home: `homedir()` is `$GEMINI_CLI_HOME` or the OS home; the config dir is `<home>/.gemini` (`settings.json`, `oauth_creds.json`, `projects.json`, `tmp/`…).
- Session files: `<config>/tmp/<project slug>/chats/session-<YYYY-MM-DDTHH-MM>-<first 8 of the id>.jsonl`, append-only. `tmp/<slug>/.project_root` holds the project folder. The first line is the header `{sessionId, projectHash, startTime, lastUpdated, kind?}`; then messages `{id, timestamp, type, content, displayContent?}` with `type` `user` (content: parts `[{text}]`), `gemini` (content string, `model`, `thoughts[{subject, description}]`, `tokens`, `toolCalls[{id, name, args, result, status, resultDisplay}]`), `info`, `warning`, `error`; and `{"$set"}`, `{"$rewindTo"}`, `{"$patch"}` records. A message is appended again, whole, when it gains tool calls (recorded only once they complete) or tokens.
- Hooks: `settings.json` `hooks` `{Event: [{matcher?, hooks: [{type: "command", command, timeout}]}]}`, timeout in milliseconds, on by default, skipped in untrusted folders. Events used: `SessionStart` (`source`), `BeforeAgent` (`prompt`), `AfterAgent`, `Notification` (`notification_type: "ToolPermission"`, `details`), `SessionEnd`. Stdin: `session_id`, `transcript_path` (empty before the first record), `cwd`, `hook_event_name`. Commands run in the shell with Gemini's environment (`TMUX_PANE` and the launcher's variables included).
- Approvals: `BeforeTool` can deny or force the dialog but never allow. The `Notification` hook is awaited right before the dialog; its `details` are `{type: edit|exec|mcp|info, title, …}` (`command` for exec, `filePath`/`originalContent`/`newContent` for edit, `serverName`/`toolName` for mcp, `urls` for info). In the dialog, `1` selects "Allow once" (always the first option when the edit is not being modified) and Escape cancels ("No, suggest changes").
- TUI: Enter submits; Ctrl+J adds a line; an Enter within 40 ms of a paste becomes a line break. `--resume <uuid>` resumes.

## Goals / Non-Goals

**Goals:** Gemini sessions in the list (live and recent), their conversation, prompts and keys, start and resume from the phone, approvals from the phone, push and live status; Claude Code and Codex unchanged.

**Non-Goals:** mode switching (Gemini does not persist its mode; yolo is never offered), worktrees (behind an experimental setting), session names (no command), status line and token usage, the one-shot call (headless runs write a session and fire `SessionStart`), subagent transcripts, custom `.toml` commands, `$rewindTo` / `$patch` (entries already shown stay).

## Decisions

- **Adapter.** `gemini.ts`: command `gemini`, `configDirEnv: 'GEMINI_CLI_HOME'`, default `~/.gemini`; new optional `configDirEnvValue(configDir)` (the parent folder for Gemini; identity elsewhere) used by the launcher, and `acceptsConfigDir(configDir)` (basename `.gemini`) checked by `resolveProfiles`, which ignores the profile with a warning otherwise. `resumeArgs: ['--resume', id]`; `worktreeArgs`, `nameArgs`, `renameCommand`, `presets`, `polish` null; `modes`, `statusLine`, `providers`, `permissionRules` false.
- **Discovery.** `findTranscripts` lists `tmp/*/chats/session-*.jsonl` modified since the cutoff and reads each header for the session id. `readSummary` reads the head: the first `user` message's text (one line) as title, the folder from `tmp/<slug>/.project_root`.
- **First-occurrence index.** `TranscriptFormat` gains an optional `upserts: true`. For such formats `TranscriptFile.sync` parses each new line once and remembers the first cursor of every entry key; `TranscriptFile.entries(line)` (used by `page`, `since` and the live stream) drops entries whose key first appeared on an earlier line. Keys are `<message id>:<part>`: `text`, `thought:<n>`, `tool:<call id>` and `result:<call id>`, so a message appended again only adds its new tool calls.
- **Tool names.** `run_shell_command` → `exec {command, workdir}`; `read_file` → `Read {file_path}`; `write_file` → `Write {file_path, content}`; `replace` → `Edit {file_path, old_string, new_string}`; `grep_search` / `search_file_content` → `Grep {pattern, path}`; `glob` → `Glob {pattern, path}`; `google_web_search` → `WebSearch {query}`; others keep their name and args. Results: the `functionResponse.response.output` (else `error`, else `resultDisplay` text), `isError` when the status is `error` or `cancelled` or the response has `error`.
- **Hooks.** New hook style `gemini-hooks`: one group per Gemini event whose `curl` posts stdin to `/hooks/<our event>` (`SessionStart`, `UserPromptSubmit`, `Stop`, `PermissionDialog`, `SessionEnd`), output discarded, timeouts `5000` ms (`SessionEnd` `3000`). `isOurHook` already matches the curl command; the generic remove keeps the user's hooks. `PermissionDialog` is a new hook event name (an agent is about to show its own approval dialog): state `waiting`, moves no handed-over request, no push of its own (the permission request pushes).
- **Approvals through keys.** `PermissionBroker.openDialog(hook)` builds the request from `details` (exec → `exec {command}`, edit → `Edit {file_path, old_string, new_string}`, mcp → `mcp__<server>__<tool>`, info → `web_fetch {urls}`, else `tool`), `rules: false`, and keeps it pending without a hook: the responder returns `{}` at once. A decision calls the injected `answerDialog(info, behavior)`; it captures the pane, checks `dialogOpen(screen)` (the "Allow once" option and the "No, suggest changes" line), sends `1` or `Escape`, and fails with `already_resolved` (request resolved as cancelled) when no dialog is on screen. The usual watch (tool result or prompt in the transcript, turn hooks) resolves it when answered in the terminal; on timeout it is handed over to the terminal as before.
- **Launcher.** `GEMINI_CLI_HOME=<parent of configDir>` when it is not `~/.gemini` (unset otherwise), `gemini` instead of `claude`, no provider block.
- **Setup and doctor.** `detectConfigDirs` adds `~/.gemini` when it holds `settings.json`, `oauth_creds.json`, `projects.json` or `tmp`; `suggestProfile` gives it `agent: 'gemini'`, id `gem`, name `Gemini`, the Gemini color. Doctor checks `gemini` on the PATH and the hooks, and prints the folder trust note.
- **Protocol tolerance.** `agent` on `Session` and `Profile` becomes `AgentIdSchema.optional().catch(undefined)`.
- **App and web.** Agent color `#E3729E` (pink, distinct from Kimi's blue and Qwen's violet, legible on the dark and light themes), code `gm`, a neutral square as the app icon (like the other non-Claude placeholders) and Gemini's star from lobe-icons as the landing mark; `canStartInWorktree` stays Claude Code and Codex.

## Risks / Trade-offs

- [Nothing was run against a live Gemini CLI] → fixture tests built from the 0.66.0 structures; the PR lists what is unverified (hook delivery, dialog keys inside tmux, paste timing).
- [Keys typed in the pane depend on the dialog's layout] → the daemon checks the dialog is on screen right before typing and gives the request back to the terminal otherwise.
- [Untrusted folders run no hooks: sessions stay read-only and approvals stay in the terminal] → said by setup, doctor and the docs; nothing breaks.
- [A cancelled turn (Escape) may not fire `AfterAgent`, leaving the session `running` until the next hook] → accepted for now.
- [Apps older than this change reject a list with a Gemini session] → the app update (OTA) ships with the daemon; `.catch` prevents this for later agents.

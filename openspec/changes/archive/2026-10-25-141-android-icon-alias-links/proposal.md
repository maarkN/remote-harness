## Why

On Android, the default app icon setting (Match theme) disables `MainActivity` and enables a per-theme activity alias that carries no `remoteharness://` / `claude-remote://` intent filter, so from then on pairing by QR code, notification links and every other deep link stop resolving (#342). The switch also throws the user back to the launcher right after the first launch, because it runs on the first `background` state, which a permission dialog already triggers, and switching the launcher activity removes the app's task.

## What Changes

- Every alternate-icon activity alias gets the same intent filters as `MainActivity` (besides its own launcher filter), generated by a config plugin in `app.config.ts`.
- On Android, a pending icon change is applied only when the user leaves the app on purpose (Home or Recents) — not when a permission dialog, the camera, a picker or a link the app opened pauses it, and not when the screen turns off. `MainActivity` reports that moment to JS with a device event.

## Impact

- `apps/mobile/app.config.ts`: two config plugins (alias intent filters, `MainActivity` leave signal).
- `apps/mobile/src/features/settings/app-icon-store.ts` / `app-icon.ts`: Android trigger moves from `AppState` to the device event.
- Native Android only; iOS behavior is unchanged. Needs a new native build (not deliverable by OTA).

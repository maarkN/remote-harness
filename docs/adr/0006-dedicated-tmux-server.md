# Agent sessions run on a dedicated tmux server

The launchers and the daemon used the user's default tmux server, so whatever their `tmux.conf` set applied to our windows (a global `destroy-unattached on` killed the `claude-remote` session as soon as the launcher's view detached, `remain-on-exit` kept dead panes alive, hooks and plugins such as tmux-resurrect acted on our windows), our sessions showed up in their `tmux ls`, and a launcher run inside their tmux took over their current client with `switch-client`. We decided that Remote Harness addresses a tmux server of its own, `tmux -L remote-harness` (the `tmuxSocket` key of `config.json`), started with a small generated config (`~/.remote-harness/tmux.conf`, written by `install` and by the daemon at start) instead of the user's: Esc delivered at once, focus events, a larger history, nothing else. Every tmux invocation of ours — the daemon's `TmuxClient`, the launchers, "Open in terminal", the `remote-harness tmux` passthrough and the demo — carries the same `-L` and `-f`. Inside tmux, a launcher compares the current client's socket with ours: a client of our server switches to the new window; a client of another server gets the session nested in the current pane, with the view's status line off, and is never switched. `tmuxConfig: "user"` sources the user's own `tmux.conf` on top of ours for those who want their bindings inside the agent's window, and `tmuxSocket: null` restores the shared default server entirely.

We rejected keeping the shared server and only replacing `switch-client` with a new window in the user's current session: a small change, but their `tmux.conf` and plugins keep governing our panes and `claude-remote` stays in their `tmux ls`, which were the complaints. We also rejected a dedicated server that, inside the user's tmux, only prints how to attach: it avoids the nested tmux, but sends the user to another terminal to see the session they just started where they typed the alias. The cost of the decision is a nested tmux when the launcher runs inside the user's own tmux (the same prefix must be pressed twice to reach the inner one, rarely needed with Claude Code), and sessions started before the change keep running on the default server, where the daemon no longer looks; `install` says how to reach them.
